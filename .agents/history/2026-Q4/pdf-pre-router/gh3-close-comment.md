Design decisions in the ADR-0004 amendment (docs/adr/0004-routing-and-auto-mode.md, A1–A7); deviations from this issue's body were deliberate and are recorded there.

- **Corrected framing:** per-page OCR routing already existed (PageRoute/INTENT_RULES); what classify_pdf offers is a better *signal source*. The issue's "falls back to the deterministic judge" was a category error — the judge only re-ranks; the classifier-unavailable fallback is the existing rule table (amendment A3).
- **Seam, not backend:** `PageOcrClassifier` Protocol + `OcrFacts` (routing/classifier.py), provider `providers/pdfinspector.py` (`resolve_classifier(None) → None` — absence is exactly the prior behavior). Augment-only: `PageSignal.classifier_needs_ocr` (True-only) ORs into `page_needs_ocr` — the classifier may add OCR-need, never remove it (A2). `plan_route` untouched; pure `apply_classifier` fold at the analysis boundary (A1).
- **`detect_pdf`, not `classify_pdf`:** 1-indexed like the IR (no normalization trap) and carries OCR reasons + table pages. Live ground truth: on an image-only first page detect returned `pages_needing_ocr=[1,2]` while classify returned `[0,1]`; upstream lib.rs confirms detection pushes `page_0idx + 1`. Facts are IR-1-based by contract; a 0-based upstream answer trips the validator → `ClassifierError`.
- **Model-free/local-only contract (A4):** detection-only, tens of ms, no OCR runtime touched; provenance via document diagnostic (`source = "pdf-inspector <version>"`, pdf_type, confidence); `feature:tables` emitted from table pages — never `feature:figures` (A5/A6).
- **CLI:** `--judge SPEC` and `--classifier SPEC` on convert (judge-style resolution; malformed spec → exit 2, unavailable provider → exit 1; absent flags byte-identical to before). A7's configurable no-heuristic path is now user-facing.
